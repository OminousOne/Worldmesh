A spatial query asks which entities are within a radius of an entity, in any group. It's how game code finds what's around an entity, like a bot looking for a target.

An entity knows the other entities in its own group exactly: `me.local()` reads them directly. Entities in other groups it learns about only through a spatial query, answered by the [spatial layer](/Worldmesh/concepts/spatial-layer/). Either way, it can read only their visible components.

## Querying

```rust
// Which entities are within 6 tiles of me, in any group?
me.query(6.0);
```

The query goes with the group's report to every Spatial Layer Cell whose area the circle touches. Move the entity, change the radius, or add cells, and see which cells get the query:

<ChunkMap mode="query" cells={3} />

Each cell answers before the group's next tick, so the results are there on the next tick:

```rust
for s in me.sensed() {
    // s.id, s.x, s.y, s.group, s.player, s.kind(), s.get::<Health>()
}
```

Results list other groups' entities only, since your own group's are already exact. They're dropped after a second: query again when you need fresher ones. The medieval example's bots query every 200 ms, staggered by id so they don't all query on the same tick.

## Using what you know

Two helpers combine both sources:

```rust
// My group's entities (exact) and others' (from the last results), within 6 tiles.
let near = me.nearby(6.0);
// What I know of one entity, if anything.
let target = me.find(id);
```

Each `Nearby` says whether it's `local` (exact and current) or from query results (a tick or two old).

## Keeping results small

By default the results list everyone in the circle, with every visible component. In a crowd that adds up: fighting bots querying every 200 ms are most of the bus traffic. A `Query` narrows who and what:

```rust
// The 5 nearest, plus my foe if it's in range, and of each only whether it's dead.
me.query(Query::within(12.0).nearest(5).target(foe).with::<Dead>());
```

- **Ask only for the components you'll read.** The medieval bots only need to know who's dead. Asking for `Dead` alone cut the results on the bus by 40% with 1,000 bots.
- **Ask for fewer entities.** `.nearest(n)` keeps the closest few; `.target(id)` always includes the one you care about.
- **Query only when you need to.** A wandering bot that never fights never queries. A bot that was just hit doesn't need to either: the hit says who and where the attacker was (`Incoming::from`). In the medieval example, Combat keeps that in a `LastHit` component and Bots reads it.

Very large results are split into several messages (at most 4,000 entities each), so none hits the bus's 1 MB message limit.
